# بوت إشعارات تليجرام — على بابك

Worker على Cloudflare بيبعت إشعار تليجرام فوري:
- **للأدمن** لما طلب جديد يتعمل.
- **للتاجر** لما الأدمن يرسله الطلب (نفس لحظة إشعار التطبيق الحالي — مفيش إشعار للتاجر عند إنشاء الطلب).
- **للمندوب** لما يتسندله طلب توصيل.

وكمان تذكيرات موقوتة لمقدمي الخدمات (كرون كل 10 دقايق):
- **تذكير قبل الميعاد المقبول بساعة.**
- **تنبيه لو حجز مستني رد من أكتر من ساعتين** (رسالة واحدة مجمعة لكل مقدم خدمة).
- **ملخص مواعيد بكرة المقبولة** الساعة 8 مساءً بتوقيت القاهرة.

التذكيرات الموقوتة مش بتقرأ Firestore: التطبيق بيعمل مرآة لبيانات الحجز في KV عن طريق
`/reminders/sync` بعد كل إنشاء/تغيير حالة، والكرون بيقرأ المرآة دي بس. كل نوع تذكير ليه مفتاح
لكل مقدم خدمة بيتخزن عن طريق `/reminders/prefs` (الافتراضي: الكل شغال).

## إشعارات المتصفح (Web Push)

الـ Worker بيبعت Web Push (VAPID + تشفير RFC 8291 بـ WebCrypto، من غير مكتبات) لنفس مفاتيح
`/notify` — يعني أي إشعار بيوصل تليجرام بيوصل المتصفح كمان، من غير ما المتصل يغير حاجة.

- `GET /push/key` — بيرجع مفتاح VAPID العام (بيتولد أول مرة وبيتخزن كامل في KV؛ الخاص ميطلعش بره أبدًا).
- `POST /push/subscribe` — بتوكن Firebase ID (زي `/link/start`)، وجسم `{subscription, keys?}`:
  الاشتراك بيتخزن تحت نفس مفاتيح التليجرام (`m:<merchantId>`، `a:<agentId>`، `role:ADMIN`) زائد `uid:<uid>` تلقائيًا.
- `POST /push/unsubscribe` — بيمسح الاشتراك من كل الفهارس.
- الاشتراك الميت (HTTP 404/410 من خدمة البوش) بيتشال تلقائيًا أثناء الإرسال.
- الـ payload اللي بيوصل للـ service worker: JSON `{title, body}`.

مفيش أسرار جديدة ولا خطوات كونسول: المفتاح بيتولد في الـ Worker نفسه.

التكلفة: صفر (Workers المجاني 100 ألف طلب/يوم، الكرون 144 مرة/يوم، KV المجاني يكفي، Bot API مجاني). مفيش أي تغيير في قواعد Firestore: الـ Worker مش بيقرأ ولا بيكتب في القاعدة خالص.

## بث الأدمن

`POST /broadcast` محمي: لازم المتصل يكون أدمن رابط تليجرام (زي ما هو). وضعين:

- **جمهور بدور** `{audience, text}` — زي ما هو من غير تغيير: تليجرام لكل المربوطين في الدور.
- **مفاتيح صريحة** `{keys: ['uid:<firebase uid>', ...], text}` — لما keys موجودة audience بيتجاهل.
  حد أقصى 100، وأي مفتاح مش بالشكل `uid:...` = 400. لكل uid: تليجرام من سجل الربط `uid:<uid>`،
  وبوش متصفح من فهرس `uid:<uid>` (payload `{title:'على بابك', body:text}`). الرد:
  `{ok, total, sent, pushed, blocked, failed}` حيث total = عدد الـ uids اللي ليها ربط أو اشتراك.
  التطبيق بيحل بيها «كل التجار / المناديب / المقدمين / المسوقين» و«شخص واحد» لقائمة uid من عنده.

## الربط محمي بإيه؟
- ربط الحساب (`/link/start` و`/link/status` و`/link/stop`) محمي بتوكن Firebase ID بتاع المستخدم نفسه — الـ Worker بيتحقق من التوقيع بمفاتيح جوجل العامة، فمحدش يقدر يربط حساب غيره.
- `/notify` محمي بسر مشترك `APP_SECRET` بين التطبيق والـ Worker (ظاهر في سورس الواجهة زي أي كود عميل — بيقلل العبث العشوائي، وأسوأ تأثير ممكن هو إشعار مزعج مش تسريب بيانات).
- `/tg/webhook` محمي بـ `WEBHOOK_SECRET` (تليجرام بيبعته في هيدر مع كل تحديث).

## خطوات النشر (بعد موافقة إسلام)

المتطلبات: Node.js 18+ و`npm i -g wrangler`، وتسجيل دخول `wrangler login` بحساب Cloudflare بتاع الموقع.

1. **إنشاء KV namespace** وحط الـ id في `wrangler.toml`:
   ```
   wrangler kv namespace create TG_LINKS
   ```
2. **اسم البوت**: حط اسم البوت اللي اتعمل من BotFather في `BOT_USERNAME` في `wrangler.toml`.
3. **الأسرار**:
   ```
   wrangler secret put BOT_TOKEN       # التوكن من BotFather (من الخزنة)
   wrangler secret put APP_SECRET      # نفس قيمة APP_SECRET في telegram-notify.js
   wrangler secret put WEBHOOK_SECRET  # نص عشوائي طويل
   ```
4. **نشر**:
   ```
   wrangler deploy
   ```
   خد رابط الـ Worker (مثل `https://ala-babk-tg-notify.<sub>.workers.dev`) وحطه في `WORKER_URL` في `telegram-notify.js`.
5. **تفعيل الـ webhook** (مرة واحدة):
   ```
   curl -X POST https://<worker-url>/tg/setup-webhook -H "x-app-secret: <APP_SECRET>"
   ```
   المفروض يرجع `{"ok":true,...}`.

## اختبار محلي
من جذر الريبو:
```
node worker/worker.test.mjs
```
بيشغّل الـ Worker محليًا بـ KV وهمي وبيغطي: مسار الربط كامل، الأكواد الغلط، إلغاء الربط، صلاحيات `/notify`، وإشعار الأدمن.
